# Навыки OmniGamer

## `approach_target`

Параметры профиля игры имеют приоритет для порогов детектора и лимитов навыка. Без профиля сохраняются прежние значения `config`. В `data/profiles/minecraft.json` хранятся синонимы запроса, раскладка движения, пороги и лимит действий/времени. Подробности схемы и CLI: [DEVELOPMENT.md](DEVELOPMENT.md).

`default_registry()` в `omnigamer/skills/registry.py` публикует описание и JSON Schema параметров для планировщика. Адаптер возвращает `SkillResult`: `REACHED` → статус `SUCCESS` и код `APPROACH_REACHED`, `REACHED_UNCONFIRMED` → `UNCONFIRMED`, `ABORT` → `ABORT`, прочие завершённые состояния → `FAILED`. У `move_pulse` и `turn` общий код `SUCCESS` означает только отправку ввода. `search_target` возвращает `TARGET_DETECTED`, а выполненное визуальное условие — `CONDITION_MET`.

Если detector теряет крупную цель, короткий `cautious_walk` допускается только по последней рамке точного запроса, которая покрывает перекрестие с профильным margin. Рамка вне перекрестия, fallback-синоним или повторное отсутствие цели переводят FSM в ограниченный поиск; потерянная цель не разрешает продолжать движение вперёд.

При начальном выборе target seed из нескольких рамок одного query используется максимальный detector score. Если ближайший кандидат уступает ему не более чем на профильный `approach_track_ambiguity_margin`, выбирается из этой группы рамка, чей центр ближе к перекрестию. Так устраняется небольшой score tie-break в пользу крошечной рамки вдали от активной цели; большой перевес detector score не переопределяется.

## Реестр базовых навыков

| Навык | Поведение и ограничения |
| --- | --- |
| `click_menu_target(target_label, intent, expected_result)` | Доступен goal-планировщику только если профиль объявляет `ui_adapters`. Проверяет совпадение `expected_result` параметра с postcondition шага и известным результатом UI-адаптера (`world_select`, `world_selected`, `gameplay`); английские и поддерживаемые русские формулировки нормализуются до этих кодов для проверки конфликта между планом и локализацией. Если title-menu geometry распознана и профиль явно задаёт `main_menu_target_transitions[target_label]`, planner заменяет пропущенное/неверное postcondition известным непосредственным переходом из профиля; следующий шаг всё равно строится заново после визуальной проверки. Непустой localized label должен совпадать с запрошенным label после нормализации; исключения `visible_world_row` и `Play selected world` принимаются только в согласованном состоянии world-list адаптера и с соответствующим postcondition. Навык получает свежий кадр, повторно локализует текстовую цель через `ground_click`, требует подтверждённую сцену меню/уверенность ≥0.85 и стабильную геометрию окна, затем посылает один левый клик через выбранный backend. Отправка возвращает `UNCONFIRMED`; переход должен подтвердить GoalExecutor по видимому `expected_result`/`success_check`. |
| `search_target(target_text, sweep)` | Ищет цель профильно настроенным детектором; число поворотов ограничено параметром sweep, `max_actions` и `max_sweep_counts`. По желанию делает два малых вертикальных осмотра. Для найденной цели сохраняет выбранный `target_seed` в evidence. |
| `interact_until_change(region, action, max_repeats)` | Выполняет именованное действие из профиля и измеряет 97-й перцентиль нормированной RGB-дельты региона (noise floor=4). При отсутствии изменения делает профильный шаг вперёд перед следующей попыткой (default 0.25 с); `interaction_retry_step_seconds=0` повторяет действие на текущем прицеле без перемещения. Minecraft использует 0 для накопления прогресса добычи на одном блоке. Дельта выше профильного `region_change` возвращает `UNCONFIRMED/REGION_CHANGE_UNCONFIRMED`; исчерпание повторов без дельты тоже возвращает `UNCONFIRMED/INTERACTION_OUTCOME_UNCONFIRMED`. В `--goal` оба результата проверяются по `expected_result`/`success_check` на кадрах до/после; уверенное подтверждение может записать `SUCCESS_VERIFIED` даже без изменения UI-региона, а неопределённый ответ не считается успехом. |
| `move_pulse(direction, seconds)` | Направление разрешается через `move_keys`; длительность не может превышать профильный `max_action_seconds`. Предложение проходит `CameraGuard`. |
| `turn(direction, amount)` | Относительный поворот ограничивается `max_turn_counts` и проходит `CameraGuard`; значение задаётся в counts, не градусах. |
| `wait_for_condition(query/region, timeout)` | Ожидает появления/исчезновения запроса детектора либо изменения crop относительно исходного кадра. Условие только по региону — визуальная дельта-эвристика. |

Для post-click проверки `VisionBrain.assess()` выбирает menu critic по `action_type="click_menu_target"`; callback goal-пути не обязан дополнительно передавать `scene_type`. Это включает menu-state поля и профильные pixel cues world-list adapter при проверке перехода.

Все реестровые исполнители требуют `recorder` или `telemetry` и дописывают общий `skill_steps.jsonl` с `schema_version`, именем навыка, событием, аргументами и финальным `SkillResult`. `tools/summarize_run.py` группирует финальные статусы по имени навыка. `run_agent.py --goal` вызывает планировщик и запускает только проверенные навыки; профильные действия и регионы передаются как enums и проверяются повторно до исполнения. Региональные изменения и финальное постусловие плана оцениваются визуальным критиком на свежих кадрах. Если промежуточный low-level навык сообщает только об отправке команды (`result_code=SUCCESS`), следующий запланированный шаг ждёт визуального подтверждения его `expected_result`/`success_check`; при blocked, unknown, ошибке или нехватке времени выполнение плана останавливается, чтобы перепланировать по новому экрану или вернуть неопределённый исход. Локально проверенные навыки (`TARGET_DETECTED`, `APPROACH_REACHED`, `CONDITION_MET`) сохраняют собственные критерии результата. Критик использует ту же локальную VLM, поэтому не является независимой истиной. `skill_outcomes` хранит аргументы и критерии успешных примеров; планировщик получает ограниченную сводку и может применить их повторно, если кадр и цель подходят. Пример доступен только если последний исход той же пары навык+цель имеет явный код `SUCCESS_VERIFIED`, `TARGET_DETECTED`, `APPROACH_REACHED` или `CONDITION_MET` и содержит аргументы; общий `SUCCESS` (в том числе отправка движения/поворота), последующая ошибка, неопределённость или неподтверждённая дельта отключают старый пример. Общий `SUCCESS` остаётся попыткой, но не увеличивает числитель success-rate; успехами считаются только указанные коды результата. Это правило свежести, а не статистическая оценка причинности или автоматическое обобщение. `--legacy` выбирает старый цикл VLM на каждом шаге. `--dry-run` записывает `would_send`, не посылает ввод и использует изолированную SQLite `:memory:`. `skill_outcomes` отдельно сохраняет неопределённые результаты; веса модели не обучаются.

После отказа навыка `GoalPlanner` отвергает точное повторение последнего неудавшегося плана и план, начинающийся с того же неудачного навыка с теми же аргументами. Затем он один раз запрашивает исправленный план с причиной валидации; если модель снова предлагает повтор, план не исполняется. Это ограничивает идентичные повторы в рамках одного `--goal`, но не гарантирует, что две разные стратегии не будут эквивалентны по смыслу.

## Измерение HUD-региона

`tools/mark_regions.py --game-id <id> --region <name> --description "..."` читает сохранённый `--frame` или захватывает видимое окно. Можно задать `--coords x1,y1,x2,y2`; preview сохраняется без изменения профиля. После проверки preview передай `--accept`, чтобы записать область. Калибровка дельты: `tools/calibrate_region_metric.py --game-id <id> --region <name> --manifest <csv> [--accept]`. CSV содержит `sample_id,before,after,class`, где class — `no_change` или `target_change`; отчёт сохраняет все измерения и запас порога. Положительные примеры должны включать реальные игровые изменения перед тем, как объявлять профиль полностью откалиброванным.

Навык запускается отдельным режимом CLI и выполняет конечный автомат над кадрами окна и ответами локального детектора текста. Цикл навыка не вызывает VisionBrain и не записывает игровой опыт в SQLite; действия берутся из общего движения и профильного `jump` recovery.

Пример запуска после запуска detector service:

```powershell
.\.venv\Scripts\python.exe run_agent.py --window "Minecraft" --game-id minecraft --skill approach_target --target "a tree trunk"
```

Сервис запускается через `start_detector.bat` и слушает только `127.0.0.1:8082`. OWLv2 возвращает нормированные рамки и задержку. `detector_score_min` задаёт нижнюю оценку, `detector_max_box_area` отбрасывает чрезмерно крупные рамки. Предобработка настраивается параметром `detector_preprocess`: `none`, `gamma`, `clahe` или `stretch`; по умолчанию выбран `stretch`, линейное растяжение яркости p2/p98.

| Параметр | Значение по умолчанию | Назначение |
|---|---:|---|
| `approach_target_deadzone_x` | 0.06 | горизонтальная зона, где цель считается центрированной |
| `approach_target_align_exit_x` | 0.09 | порог выхода из выравнивания (гистерезис) |
| `approach_target_calibration_counts` | 12 | начальный пробный поворот |
| `approach_target_walk_duration` | 0.5 с | обычный импульс движения вперёд |
| `approach_target_reach_height` | 0.8 | минимальная высота рамки для осторожного шага вперёд после пропуска цели; альтернатива — касание верхнего края |
| `approach_target_reach_top_y` | 0.02 | допуск касания рамкой верхнего края |
| `approach_target_reach_min_width` | 0.10 | минимальная ширина рамки для сигнала близости |
| `approach_target_reach_center_x` | 0.15 | максимальное смещение центра от середины кадра |
| `approach_target_reach_center_stability` | 0.05 | допустимое смещение центра между двумя кадрами |
| `approach_track_max_center_shift` | 0.35 (общий), 0.2 (Minecraft) | максимальный скачок центра рамки до потери привязки |
| `approach_track_ambiguity_margin` | 0.02 | минимальная разница расстояний между двумя кандидатами, чтобы выбрать ближайший трек |
| `approach_reach_crosshair_margin` | 0.05 (общий), 0.08 (Minecraft) | минимальный отступ перекрестия от краёв рамки при REACHED |
| `approach_target_max_look_counts` | 30 | ограничение одного корректирующего поворота |
| `approach_target_close_target_held_impulses` | 2 | осторожные импульсы после потери близкой цели |
| `approach_target_close_target_held_duration` | 0.25 с | длительность осторожного импульса |
| `approach_target_max_impulses` | 40 | общий лимит команд ввода навыка, включая повороты камеры; число импульсов движения записывается отдельно |
| `approach_target_max_seconds` | 120 с | предел времени |
| `approach_target_lost_frames` | 3 | пропусков до ограниченного поиска |
| `approach_target_lost_search_turns` | 6 | максимум поворотов поиска |

При уже выбранной цели сначала отбрасываются кандидаты за `approach_track_max_center_shift`, остальные ранжируются по сдвигу центра, затем с меньшим весом учитывают изменение ширины/высоты и IoU. Если composite-cost двух рамок отличается не больше `approach_track_ambiguity_margin` (default 0.02), наблюдение считается неоднозначным и привязка не обновляется. Навык делает новое наблюдение без движения; две последовательные неоднозначные детекции завершают навык со статусом `UNCONFIRMED`. В `--goal` успешный `search_target` передаёт выбранный seed непосредственно следующему `approach_target`, если нормализованный текст цели совпадает; локальная recovery-цепочка применяет то же правило. Seed проходит валидацию границ/score/площади и задаёт начальный центр трекинга. При отсутствии подходящего seed первый кандидат выбирается как раньше — по максимальному score. Query-политика поиска и подхода общая: сначала исходный query, затем профильные fallback с проверкой специфичности. Fallback-запросы могут помогать искать, выравнивать камеру и приближаться, но точное состояние `REACHED` требует рамку исходного запроса. Геометрия рамок не устанавливает физическую идентичность объекта; архивные различия рамок не доказывают переключение физической цели, а поведение handoff ещё не проверено на живом подходе.

Если после порога потери поисковый поворот возвращает единственную удалённую рамку, она становится кандидатом повторного захвата, а не сразу новой целью. Кандидат должен снова появиться в пределах `approach_track_max_center_shift`; несколько удалённых рамок сохраняют неопределённость. Это предотвращает вечный отказ из-за старой экранной координаты, не доказывая, что рамка относится к тому же физическому объекту.

После нескольких пропусков цели короткий ограниченный шаг разрешается только если последняя рамка остаётся горизонтально центрированной и выше `approach_target_reach_height` (либо касается верхнего края по `approach_target_reach_top_y`). Профильный порог применяется непосредственно; он не означает `REACHED` и не подтверждает взаимодействие.

Состояния: `ACQUIRE` выбирает рамку, калибрует камеру или выполняет боковой recovery; `ALIGN` поворачивает камеру к цели; `ADVANCE` отправляет короткий `w`; `REACHED` требует касания верхнего края, достаточной ширины и двух последовательных кадров, где рамка перекрывает перекрестие с margin. Если первый кадр уже удовлетворяет критерию, второй получают без движения персонажа; если горизонтально центрированная рамка не покрывает перекрестие по вертикали, выполняется небольшой look up/down с повторной детекцией. Геометрия рамки всё ещё может включать траву/склон и не гарантирует семантическое попадание в узкий ствол. Если три кадра подряд пропущены после крупной центрированной цели, `CLOSE_TARGET_HELD` выполняет ограниченное число осторожных импульсов; если цель не появилась снова, результат — отдельный `REACHED_UNCONFIRMED`, не подтверждённый успех. Другие потери используют ограниченный `LOST`-поиск. После первой боковой коррекции повторное плато запускает профильное число прыжков вперёд (по умолчанию 1, Minecraft 2); каждый совмещает клавишу движения и именованный `jump`, если клавиша не запрещена, длительность ограничена 0.75 с и `max_action_seconds`. Если плато сохраняется, делается одна боковая коррекция в противоположную сторону; затем `BLOCKED` завершает навык. В живых попытках прыжок дал рост рамки 0.294, но подходы завершались потерей/блокировкой либо исчерпывали общий лимит ввода до добычи. `TIMEOUT` завершает по лимиту; `ABORT` завершает при остановке или недоступном детекторе.

Для текстов цели, содержащих `tree` или `trunk`, сначала проверяется исходный запрос, затем при отсутствии валидной рамки — `a tree`. Рамка подстраховочного запроса должна быть не шире половины кадра и доходить ниже верхней трети; геометрически чрезмерно широкие тонкие полосы отклоняются. При первом выборе без seed выбирается лучший score; далее — рамка, ближайшая к центру последней. После поворота без рамки навык повторно захватывает кадр и запускает детекцию на месте, прежде чем учесть пропуск. Коэффициент камеры хранится в `data/calibration.json` по `game_id`; единица — нормированный горизонтальный сдвиг рамки на один input count, не counts на радиан. Канонический ключ профиля — `normalized_error_per_camera_count`; старый `camera_counts_per_radian` читается без преобразования в его историческом фактическом смысле. Ввод ограничен поворотом и клавишами `w`, `a`, `d`; ввод освобождается при выходе.

Телеметрия навыка сохраняется отдельно в `skill_steps.jsonl`, изображения до/после итераций и финальный кадр — в `frames/`. Для каждой итерации записываются ответы детектора до фильтров, запросы, параметры предобработки и выбранный источник рамки. `tools/summarize_run.py` выводит состояние, число итераций, время, задержку детектора и историю высоты рамки. Офлайн-сухой прогон на кадрах не подтверждает безопасность или достижение цели в живой игре.

Для `--goal` добывающие действия задаются явно в профиле через `mine_actions`; тип кнопки сам по себе не определяет игровую семантику. Перед таким действием `GoalExecutor` запускает профильный visual preflight и fail-closed блокирует ввод при отсутствии уверенных фактов, timeout, заметном изменении кадра или появлении меню. Текущий локальный Minecraft-профиль перечисляет `primary_hold`. Этот preflight не доказывает разрушение блока; результат взаимодействия по-прежнему проверяется отдельным postcondition-критерием.

### Офлайн-замер F2

Экспериментальная настройка детектора проверялась на локальной выборке кадров; результаты зависят от данных, порогов и модели. Эти измерения не подтверждают переносимость навыка на произвольные игры.

Для профиля `mine_requires_target_at_crosshair` факт `target_at_crosshair=true` допускается только из текущего confident/usable preflight (confidence не ниже 0.85 и достаточное evidence). Одного положительного boolean из сомнительной оценки недостаточно: guard выдаёт `wait`. Это условие независимо от `result` оценки действия: `unknown` не запрещает использовать уверенные факты положения цели, но и не означает подтверждённый игровой прогресс.
