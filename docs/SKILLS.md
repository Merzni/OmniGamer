# Навыки OmniGamer

## `approach_target`

Параметры профиля игры имеют приоритет для порогов детектора и лимитов навыка. Без профиля сохраняются прежние значения `config`. В `data/profiles/minecraft.json` хранятся синонимы запроса, раскладка движения, пороги и лимит действий/времени. Подробности схемы и CLI: [DEVELOPMENT.md](DEVELOPMENT.md).

`default_registry()` в `omnigamer/skills/registry.py` публикует описание и JSON Schema параметров для планировщика. Адаптер возвращает `SkillResult`: `REACHED` → `SUCCESS`, `REACHED_UNCONFIRMED` → `UNCONFIRMED`, `ABORT` → `ABORT`, прочие завершённые состояния → `FAILED`. Общий формат записей навыков описан ниже.

## Реестр базовых навыков

| Навык | Поведение и ограничения |
| --- | --- |
| `search_target(target_text, sweep)` | Ищет цель профильно настроенным детектором; число поворотов ограничено параметром sweep, `max_actions` и `max_sweep_counts`. По желанию делает два малых вертикальных осмотра. |
| `interact_until_change(region, action, max_repeats)` | Выполняет именованное действие из профиля и измеряет 97-й перцентиль нормированной RGB-дельты региона (noise floor=4). При отсутствии изменения делает профильный шаг вперёд перед следующей попыткой (default 0.25 с); `interaction_retry_step_seconds=0` повторяет действие на текущем прицеле без перемещения. Minecraft использует 0 для накопления прогресса добычи на одном блоке. Дельта выше профильного `region_change` возвращает `UNCONFIRMED/REGION_CHANGE_UNCONFIRMED`, а не успех; режим `--goal` применяет отдельную проверку указанного `success_check` по паре кадров и только затем может записать `SUCCESS_VERIFIED`. |
| `move_pulse(direction, seconds)` | Направление разрешается через `move_keys`; длительность не может превышать профильный `max_action_seconds`. Предложение проходит `CameraGuard`. |
| `turn(direction, amount)` | Относительный поворот ограничивается `max_turn_counts` и проходит `CameraGuard`; значение задаётся в counts, не градусах. |
| `wait_for_condition(query/region, timeout)` | Ожидает появления/исчезновения запроса детектора либо изменения crop относительно исходного кадра. Условие только по региону — визуальная дельта-эвристика. |

Все реестровые исполнители требуют `recorder` или `telemetry` и дописывают общий `skill_steps.jsonl` с `schema_version`, именем навыка, событием, аргументами и финальным `SkillResult`. `tools/summarize_run.py` группирует финальные статусы по имени навыка. `run_agent.py --goal` вызывает планировщик и запускает только проверенные навыки; профильные действия и регионы передаются как enums и проверяются повторно до исполнения. `success_check` для изменения региона оценивает отдельный визуальный критик на свежей паре кадров. Он использует ту же локальную VLM, поэтому не является независимой истиной. Если критик недоступен, не уверен или не подтвердил прогресс, шаг не считается успешным. `skill_outcomes` хранит аргументы и критерии проверенных успешных примеров; планировщик получает ограниченную сводку и может применить их повторно, если кадр и цель подходят. Ошибочные и неопределённые попытки не предлагаются как удачные примеры. `--legacy` выбирает старый цикл VLM на каждом шаге. `--dry-run` записывает `would_send`, не посылает ввод и использует изолированную SQLite `:memory:`. Таблица `skill_outcomes` считает успехом только `SUCCESS`/`SUCCESS_VERIFIED` и отдельно сохраняет неопределённые результаты; веса модели не обучаются.

## Измерение HUD-региона

`tools/mark_regions.py --game-id <id> --region <name> --description "..."` читает сохранённый `--frame` или захватывает видимое окно. Можно задать `--coords x1,y1,x2,y2`; preview сохраняется без изменения профиля. После проверки preview передай `--accept`, чтобы записать область. Калибровка дельты: `tools/calibrate_region_metric.py --game-id <id> --region <name> --manifest <csv> [--accept]`. CSV содержит `sample_id,before,after,class`, где class — `no_change` или `target_change`; отчёт сохраняет все измерения и запас порога. Положительные примеры должны включать реальные игровые изменения перед тем, как объявлять профиль полностью откалиброванным.

Навык запускается отдельным режимом CLI и выполняет конечный автомат над кадрами окна и ответами локального детектора текста. Цикл навыка не вызывает VisionBrain и не записывает игровой опыт в SQLite; действия берутся из общего движения и профильного `jump` recovery.

Пример запуска после запуска detector service:

```powershell
.\.venv\Scripts\python.exe run_agent.py --window "Minecraft" --game-id minecraft --skill approach_target --target "a tree trunk"
```

Сервис запускается через `start_detector.bat` и слушает только `127.0.0.1:8082`. OWLv2 возвращает нормированные рамки и задержку. `detector_score_min` задаёт нижнюю оценку, `detector_max_box_area` отбрасывает чрезмерно крупные рамки. Предобработка настраивается параметром `detector_preprocess`: `none`, `gamma`, `clahe` или `stretch`; по умолчанию выбран `stretch`, линейное растяжение яркости p2/p98.

| Параметр | Значение по умолчанию | Назначение |
|---|---:|---|
| `approach_target_deadzone_x` | 0.06 | горизонтальная зона, где цель считается центрированной |
| `approach_target_align_exit_x` | 0.09 | порог выхода из выравнивания (гистерезис) |
| `approach_target_calibration_counts` | 12 | начальный пробный поворот |
| `approach_target_walk_duration` | 0.5 с | обычный импульс движения вперёд |
| `approach_target_reach_top_y` | 0.02 | допуск касания рамкой верхнего края |
| `approach_target_reach_min_width` | 0.10 | минимальная ширина рамки для сигнала близости |
| `approach_target_reach_center_x` | 0.15 | максимальное смещение центра от середины кадра |
| `approach_target_reach_center_stability` | 0.05 | допустимое смещение центра между двумя кадрами |
| `approach_track_max_center_shift` | 0.35 (общий), 0.2 (Minecraft) | максимальный скачок центра рамки до потери привязки |
| `approach_track_ambiguity_margin` | 0.02 | минимальная разница расстояний между двумя кандидатами, чтобы выбрать ближайший трек |
| `approach_reach_crosshair_margin` | 0.05 (общий), 0.08 (Minecraft) | минимальный отступ перекрестия от краёв рамки при REACHED |
| `approach_target_max_look_counts` | 30 | ограничение одного корректирующего поворота |
| `approach_target_close_target_held_impulses` | 2 | осторожные импульсы после потери близкой цели |
| `approach_target_close_target_held_duration` | 0.25 с | длительность осторожного импульса |
| `approach_target_max_impulses` | 40 | общий лимит команд ввода навыка, включая повороты камеры; число импульсов движения записывается отдельно |
| `approach_target_max_seconds` | 120 с | предел времени |
| `approach_target_lost_frames` | 3 | пропусков до ограниченного поиска |
| `approach_target_lost_search_turns` | 6 | максимум поворотов поиска |

При уже выбранной цели трекер выбирает ближайший центр рамки в пределах `approach_track_max_center_shift`. Если две рамки имеют почти одинаковую геометрическую близость (разница расстояний не больше `approach_track_ambiguity_margin`, default 0.02 нормированной ширины/высоты кадра), он помечает наблюдение неоднозначным и не обновляет привязку. Навык делает новое наблюдение без движения; две последовательные неоднозначные детекции завершают навык со статусом `UNCONFIRMED`. Fallback-запросы могут помогать искать, выравнивать камеру и приближаться, но точное состояние `REACHED` требует рамку исходного запроса. Это не устанавливает физическую идентичность объекта и может завершить попытку при симметричной сцене.

Состояния: `ACQUIRE` выбирает рамку, калибрует камеру или выполняет боковой recovery; `ALIGN` поворачивает камеру к цели; `ADVANCE` отправляет короткий `w`; `REACHED` требует касания верхнего края, достаточной ширины и двух стабильных кадров, где рамка перекрывает перекрестие с margin; если горизонтально центрированная рамка не покрывает перекрестие по вертикали, выполняется небольшой look up/down с повторной детекцией. Геометрия рамки всё ещё может включать траву/склон и не гарантирует семантическое попадание в узкий ствол. Если три кадра подряд пропущены после крупной центрированной цели, `CLOSE_TARGET_HELD` выполняет ограниченное число осторожных импульсов; если цель не появилась снова, результат — отдельный `REACHED_UNCONFIRMED`, не подтверждённый успех. Другие потери используют ограниченный `LOST`-поиск. После первой боковой коррекции повторное плато запускает профильное число прыжков вперёд (по умолчанию 1, Minecraft 2); каждый совмещает клавишу движения и именованный `jump`, если клавиша не запрещена, длительность ограничена 0.75 с и `max_action_seconds`. Если плато сохраняется, делается одна боковая коррекция в противоположную сторону; затем `BLOCKED` завершает навык. В живых попытках прыжок дал рост рамки 0.294, но подходы завершались потерей/блокировкой либо исчерпывали общий лимит ввода до добычи. `TIMEOUT` завершает по лимиту; `ABORT` завершает при остановке или недоступном детекторе.

Для текстов цели, содержащих `tree` или `trunk`, сначала проверяется исходный запрос, затем при отсутствии валидной рамки — `a tree`. Рамка подстраховочного запроса должна быть не шире половины кадра и доходить ниже верхней трети; геометрически чрезмерно широкие тонкие полосы отклоняются. При первой цели выбирается лучший score; далее — рамка, ближайшая к центру последней. После поворота без рамки навык повторно захватывает кадр и запускает детекцию на месте, прежде чем учесть пропуск. Коэффициент камеры хранится в `data/calibration.json` по `game_id`. Ввод ограничен поворотом и клавишами `w`, `a`, `d`; ввод освобождается при выходе.

Телеметрия навыка сохраняется отдельно в `skill_steps.jsonl`, изображения до/после итераций и финальный кадр — в `frames/`. Для каждой итерации записываются ответы детектора до фильтров, запросы, параметры предобработки и выбранный источник рамки. `tools/summarize_run.py` выводит состояние, число итераций, время, задержку детектора и историю высоты рамки. Офлайн-сухой прогон на кадрах не подтверждает безопасность или достижение цели в живой игре.

### Офлайн-замер F2

Экспериментальная настройка детектора проверялась на локальной выборке кадров; результаты зависят от данных, порогов и модели. Эти измерения не подтверждают переносимость навыка на произвольные игры.
