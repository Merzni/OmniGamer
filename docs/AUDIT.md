# Матрица технического аудита

Срез 2026-11-18. Матрица фиксирует проверенные исходники, выполненные исправления и оставшиеся гипотезы. В повторном read-only doctor VLM/detector ответили HTTP 200, VLM прошла JSON Schema probe, detector вернул 2 рамки; доступ к input desktop завершился WinError 5, `SendInput` не вызывался. Два последовательных live `--goal --dry-run` на цели перехода выбрали `click_menu_target` для «Одиночная игра», по одному плановому шагу и 0 вводов каждый. Контрольный dry-run с исходной игровой целью «Добудь дерево» дал тот же первый UI-навык и не предложил `interact_until_change` по hotbar; вводов 0. Прямой read-only `ground_click` на текущем кадре вернул `main_menu`, confidence 0.95; target label совпал с запросом и оба expected result нормализовались в `world_select`, вводов 0. Ранее после read-only grounding выполнялся один адресованный `PostMessage` клик на главном меню: свежий кадр не изменился, переход остался неподтверждённым. Три прежних ограниченных legacy-прогона также остановились до ввода на gate локализатора (в третьем явно указан `scene_type=unknown`).

Повторный `--dry-run` 2026-11-18 на окне `Minecraft* 26.3` за 68.1 с выбрал только `click_menu_target` для метки `Одиночная игра`, с ожидаемым переходом к списку одиночных миров; зафиксировано 0 вводов. Это подтверждает исправление выбора навыка в одном текущем кадре, не доставку клика/перехода. Код дополнительно ограничивает `interact_until_change`, `move_pulse`, `turn`, `approach_target` и `search_target`, когда профильный UI-адаптер распознаёт геометрию меню; валидатор плана также отвергает эти навыки в распознанном меню, а неизвестная геометрия не активирует локальный запрет. Повторная read-only диагностика прошла VLM schema и detector probe; доступ к input desktop отказан с WinError 5.

После добавления геометрического planner gate выполнен ещё один `--dry-run` на том же открытом окне: `click_menu_target` / `Одиночная игра` / `World selection menu appears`, 0/60 вводов, суммарно 56.7 с. Это подтверждает, что новый фильтр не скрывает нужный UI-навык в распознанном меню; это один прогон и он не проверяет фактический переход. Полный локальный suite после изменения: 293 unittest; pyflakes без замечаний.

Аудит backend capabilities нашёл несовпадающий контракт в goal и legacy путях: `WindowInputController.move_camera()` всегда отказывает, а GoalPlanner прежде не учитывал фактический backend. Goal путь уже фильтрует и проверяет `turn`/`search_target`/`approach_target` по effective backend, прямой `approach_target` отказывает до capture. Дополнительная регрессия закрывает legacy цикл: предложенный VLM `look` для `window` преобразуется до ввода в `wait`, причина попадает в отказ, запись опыта помечается `learnable=0`/неэффективной; `move_camera()` не вызывается. Живой 3D-поворот не проверялся.

## Границы результатов

- `approach_target` сообщает о геометрически подтверждённом приближении, а не о добыче или получении предмета.
- `SUCCESS_VERIFIED` для goal-взаимодействия означает, что одна отдельная проверка той же VLM уверенно оценила переданный критерий. Это не независимый источник истины.
- SQLite-изменения схемы проверены на временной базе; пользовательская `data/memory.db` не открывалась и не изменялась во время аудита.
- Результаты живых экспериментов, упомянутые в исторической документации, не перепроверялись в этой фазе и не публикуются как свежая валидация.
- Свежий read-only doctor подтвердил локальные VLM/detector probes и захват Minecraft-кадра, но Windows отказал в `OpenInputDesktop` (WinError 5); `SendInput` не вызывался, и игровой переход не подтверждён.
