Проект находится на стадии прототипа. Сохраняется опыт и проверенные маршруты меню; универсальное пространственное планирование и гарантированная мгновенная остановка пока не реализованы. Фактическое поведение и ограничения описаны в документах выше.

Для запуска требуется Python 3.11; зависимости приложения перечислены в `requirements.txt`.
Для разработки установите `requirements-dev.txt`. Детектор работает в отдельном окружении;
его пакеты и выбор CUDA-совместимого PyTorch описаны в `requirements-detector.txt`.

**OmniGamer** — прототип автономного игрового агента для Windows, рассчитанный на разные жанры и игровые окна:
- Смотрит на экран через компьютерное зрение (без прямого API к игре).
- По умолчанию использует общий `SendInput` Windows для мыши/камеры и клавиатуры с видимым розовым AI-указателем; альтернативный оконный режим не поддерживает 3D-поворот.
- Учится на собственном опыте методом проб и ошибок (без необходимости человеку играть заранее).
- Комментирует происходящее на русском языке в реальном времени.

## 🧠 Как бот учится сам (как человек):

1. **Разведка и распознавание (Perception)**:
   - Делает скриншот целевого окна и передает его локальной мультимодальной VLM (например, Qwen3.5-4B Vision).
   - Модель находит кнопки, диалоги, баннеры, шкалы здоровья, персонажей или 3D-объекты.
2. **Пробы и ошибки (Trial & Error)**:
   - Бот выбирает гипотезу действия (клик по кнопке, свайп меню, нажатие клавиши).
   - Выполняет действие и делает повторный снимок через короткую паузу.
3. **Оценка изменения (Outcome & Reward Delta)**:
   - Дельта картинки означает только изменение экрана. Успешный переход меню требует отдельной оценки результата и подтверждения следующим наблюдением.
   - Попытки без заметного изменения экрана учитываются в памяти. После двух таких попыток агент получает предупреждение и перепланирует; если повтор сохраняется на том же экране, действие заменяется коротким ожиданием. Это эвристика, а не доказательство бесполезности действия.
4. **Накопление памяти (Episodic Memory)**:
   - Опыт сохраняется в SQLite `data/memory.db` отдельно для каждой игры. В знакомом меню бот сопоставляет состояние и вид кнопки с проверенными действиями, выбирает путь до игры глубиной до четырёх переходов и повторяет только один шаг с новой проверкой. Обучения весов модели нет.

## 🚀 Быстрый старт:

### 1. Запуск локальных моделей

Рекомендуемый запуск обоих сервисов: задайте переменные окружения `OMNIGAMER_LLAMA_SERVER`,
`OMNIGAMER_VLM_MODEL`, `OMNIGAMER_VLM_PROJECTOR`; для отдельного окружения детектора задайте
`OMNIGAMER_DETECTOR_PYTHON`. Запустите `start_all.bat`. Скрипт ожидает `/health`, PID-метаданные
пишет в `data/runtime/`, журналы — в `data/logs/`. `stop_all.bat` завершает только процессы с
совпавшей командой/исполняемым файлом. Скрипты не открывают игру и не отправляют ввод.

### 2. Запуск панели управления:
Запустите файл:
```bat
start_dashboard.bat
```
Откроется браузер по адресу: **`http://127.0.0.1:8765`**.

Панель по умолчанию доступна только на этом компьютере (`127.0.0.1`). Чтобы открыть её в локальной сети, запускайте сервер с `--host 0.0.0.0`; панель не имеет авторизации, поэтому не публикуйте этот порт в недоверенной сети или интернете.

В веб-интерфейсе:
1. Выберите окно с игрой (например, `LDPlayer` или `Minecraft`) из выпадающего списка.
2. Укажите стабильный **профиль памяти**, например `minecraft-survival`, и нажмите **«Привязаться к игре»**. Используйте то же имя в следующих запусках; для другой игры/режима задайте другое. Без имени память привязывается к заголовку окна. Старые записи без указания игры сохраняются отдельно в `legacy`.
3. Нажмите **«Сделать 1 шаг»** (для разовой проверки) или **«Авто-игра»** (для непрерывного исследования).

### Цель через реестр навыков

CLI требует выбрать режим явно. Сухой план: `python run_agent.py --game-id <id> --goal "<цель>" --dry-run --window "<заголовок>"`;
он запрашивает VLM и пишет `would send`, не посылая ввод и не переводя окно на передний план. Окно должно оставаться видимым и не перекрытым. Для исполнения проверенного плана уберите `--dry-run`;
старый цикл VLM на каждом шаге выбирается только через `--legacy`.

### Профиль новой игры за 10 шагов

1. Скопируйте `data/profiles/_template.json` в `data/profiles/<id>.json` и задайте уникальный `game_id`.
2. Укажите подстроку заголовка окна и `input_backend`.
3. Задайте `camera_type` и клавиши четырёх направлений.
4. Опишите именованные `actions` с типом, клавишей/кнопкой и длительностью.
5. Внесите опасные клавиши/сочетания в `forbidden_keys`.
6. Задайте `motion_limits` и начальные `thresholds`; `ui_adapters` оставьте пустым, кроме профильно опознанной раскладки.
7. Сохраните кадр без управления игрой; размечайте `tools/mark_regions.py --game-id <id> --frame <кадр> --region <name> --coords x1,y1,x2,y2`, проверьте preview и только затем запишите его с `--accept`.
8. Соберите CSV пар кадров до/после контролируемого изменения и запустите `tools/calibrate_region_metric.py`; synthetic-only положительная выборка не завершает калибровку.
9. Запустите `python -m omnigamer.doctor --game-id <id> --window "<заголовок>"` и устраните проблемы.
10. Выполните `--goal ... --dry-run`, изучите `data/runs/<run_id>/skill_steps.jsonl` и отдельно подтвердите игровой тест.

По разрешению владельца стартовый режим — «Общий системный ввод»: он двигает общую мышь и использует фокус игры. Розовый маркер остаётся. Альтернативный режим «Отдельный указатель» не двигает системную мышь и не перехватывает фокус. Окно игры должно оставаться видимым. Raw Input/3D-игры могут игнорировать сообщения или самостоятельно захватывать общий курсор; полноценная изоляция требует отдельной сессии/VM. Режим общего ввода выбирается явно, автоматического переключения нет.

Агент играет непрерывно: сам выбирает следующий опыт, исследует механику и использует накопленные наблюдения. Прохождение игры или отдельное достижение не завершает автоигру. При длительном застревании он меняет стратегию: осматривает другой путь и пробует короткий обход при подтверждённой опоре. Проверки моделью могут ошибаться и добавляют задержку; результаты опыта видны отдельно от комментария персонажа. Обучения весов нейросети сейчас нет.

## 🛡️ Безопасность (Failsafe Guard):
Для аварийной остановки нажмите F12: агент опросит клавишу в активной Windows-сессии, установит stop-флаг и попробует отпустить удерживаемые им клавиши/кнопки. Проверка идёт каждые 10 мс, но Windows может не сообщить состояние клавиши на secure desktop или в другой сессии. Уже отправленный HTTP-запрос VLM не отменяется на стороне сервера, хотя агент прекращает его ждать. Также остаётся failsafe: переместите системную мышь в левый верхний угол `(0, 0)`.

## 📁 Структура проекта:
```
OmniGamer/
├── omnigamer\
│   ├── capture.py        # Захват любого окна по HWND / заголовку
│   ├── controls.py       # SendInput мышь и клавиатура, плавные траектории
│   ├── vision_brain.py   # Инференс локальной VLM через OpenAI API
│   ├── memory.py         # Хэширование состояний, SQLite, учет дельты и мертвых зон
│   ├── personality.py    # Neuro-сама комментарии, эмоции и логи
│   ├── agent.py          # Основной цикл Observe -> Act -> Learn
│   └── dashboard\        # Веб-интерфейс стримера (FastAPI + HTML5)
├── run_agent.py          # Запуск из командной строки
├── run_dashboard.py      # Запуск сервера веб-панели
├── start_qwen.bat        # Запуск локальной VLM
└── start_dashboard.bat   # Запуск дашборда
```
