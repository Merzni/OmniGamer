# Правила для агентов OmniGamer

Перед работой прочитай `docs/PROJECT_CONTEXT.md`, `docs/STATUS.md` и `docs/DEVELOPMENT.md`. Для непрерывной игры и камеры смотри `docs/CONTINUOUS_PLAY.md`; для отдельного указателя и памяти меню — `docs/POINTER_AND_MENU_MEMORY.md`.

Общайся с владельцем и веди проектную документацию по-русски. Считай исходный код источником истины. Сохраняй архитектуру screen-only → локальная VLM → native input и не используй внутренние игровые API без прямой задачи владельца. При изменении поведения обновляй соответствующую документацию и `docs/STATUS.md`, указывая только подтверждённые результаты.

Не добавляй в GitHub виртуальные окружения, базы, кадры, логи, телеметрию, локальные настройки, секреты и пользовательские данные. Используй `.gitignore`; перед коммитом проверь staged-файлы и убедись, что в них нет таких артефактов. Не включай существующие посторонние изменения в коммит.

## Обязательный GitHub workflow

- После каждой задачи, которая изменила файлы проекта, создай коммит и отправь его в настроенный GitHub remote `origin`. Это относится и к изменениям только документации.
- Перед коммитом проверь `git status`, добавь в индекс только файлы текущей задачи и просмотри `git diff --cached`.
- Создавай обычный коммит с коротким содержательным сообщением. Не изменяй историю опубликованных коммитов через amend, rebase или force push.
- После коммита выполни `git push origin HEAD`. Проверь, что удалённая ветка указывает на отправленный коммит и рабочее дерево не содержит незапланированных изменений.
- Не создавай пустые коммиты, если файлы проекта не менялись.
- Если отсутствует авторизация, remote или доступ на запись, сохрани локальный коммит, сообщи точную причину и попроси владельца устранить только этот блокер. Не проси присылать пароль или токен в чат и не утверждай, что публикация завершена, пока push не подтверждён.

Не запускай тесты и проверки, не запрошенные владельцем или инструкциями проекта. Если проверки обязательны, дождись их завершения до публикации.
